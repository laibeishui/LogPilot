# LogPilot V0.1 使用指南

> 文档编号：07｜日期：2026-10-17
> 面向对象：第一次把 LogPilot 跑起来并完整用一遍的人（开发 / 运维 / 值班都适用）。
> 与部署细节相关的内容（端口、卷、开机自启、systemd）见 [`06_LogPilot_V0.1_部署指南.md`](06_LogPilot_V0.1_部署指南.md)；本文只讲「装上之后怎么用」。

本文按一次完整的上手路径组织：

```
① 跑起来 → ② 建管理员 → ③ 建项目 → ④ 发 Token → ⑤ 接入日志
        → ⑥ 检索/实时跟随 → ⑦ 看总览 → ⑧ 配告警 → ⑨ 诊断与排障
```

---

## 1. 五分钟跑起来（最简部署速览）

LogPilot 运行期只需要**两个组件**：LogPilot（Web + API + SQLite）和 VictoriaLogs（日志引擎）。

最省事的方式是 Docker 全栈：

```bash
cp deploy/.env.example deploy/.env
docker compose -f deploy/compose.yml --env-file deploy/.env up -d --build
```

启动后访问：

| 地址 | 用途 |
|---|---|
| `http://localhost:8080` | 控制台入口（未初始化会自动跳到 `/setup`）|
| `http://localhost:8080/health/live` | 存活探针 |
| `http://localhost:8080/health/ready` | 就绪探针（含各组件状态）|

> 其他两种部署方式（Windows 本机 + Docker 跑 VL；Linux 本机 systemd）见部署指南，操作界面完全一致。

---

## 2. 第一次进入：创建管理员

首次打开 `http://localhost:8080` 会自动进入 `/setup`「创建管理员」页：

| 字段 | 说明 |
|---|---|
| 管理员账号 * | 登录用户名，最长 64 字符 |
| 显示名称 | 可选，控制台右上角展示 |
| 密码 * | **至少 8 位**，最长 128 字符 |
| 确认密码 * | 两次输入需一致 |

点击「创建并进入系统」后自动登录并回到总览页。**初始化只能执行一次**，之后 `/setup` 不再接受提交。账号信息保存在 SQLite，重启不丢。

日常登录入口是 `/account/login`（账号 + 密码）。右上角「退出」会注销当前登录态并跳回登录页。

## 3. 创建项目

进入左侧导航「**项目管理**」。

1. 点右上角「**+ 新建项目**」，填写：
   - **项目名称**（必填，最长 100）
   - **项目编码**：英文短标识，例如 `hilink`（最长 64）
   - **说明**：可选（最长 500）
2. 点「创建」，列表出现新项目，状态为「启用」。

列表每行操作：

| 操作 | 说明 |
|---|---|
| **接入** | 跳转到接入中心，并自动选中该项目 |
| **停用 / 启用** | 停用后该项目下所有 Token 立即无法写入日志（检索仍可查历史），确认框会二次提示 |

> 项目是 LogPilot 里数据隔离的最小单位：查询、告警、Token 全部挂在项目下。

---

## 4. 生成接入 Token（API Key）

进入左侧导航「**接入中心**」（也可从项目列表点「接入」直接带着项目跳过来）。

1. 在「选择项目」下拉里确认项目。
2. 填「**密钥名称**」（例如 `api-prod`，留空则默认 `default`）。
3. 点「**生成 Token**」。

生成后会出现一块橙色提示区，**明文 Token 只显示这一次**：

- Token 形如 `lp_xxxxxxxx...`，固定以 `lp_` 开头；
- 请立即点「复制 Token」并安全保存；**关闭页面后无法再次查看明文**（数据库只存哈希）。

下方列表展示已有密钥：

| 列 | 说明 |
|---|---|
| 名称 | 生成时填写的名称 |
| 前缀 | Token 前缀，用于区分 |
| 状态 | 启用 / 已撤销 |
| 创建时间 | 生成时间 |
| 操作 | 「撤销」——撤销后该 Token 立即失效（不可恢复，需重新生成）|

> 建议按环境发独立 Token（如 `api-dev` / `api-prod`），便于单独撤销。

## 5. 接入日志（三种方式）

LogPilot 提供两个写入入口，均用 `Authorization: Bearer <你的 Token>` 鉴权；**`projectId` 由 Token 决定，请求里自带的 `projectId` 会被忽略**。

### 5.1 OTLP/HTTP（推荐，走标准 SDK）

主入口，兼容 OpenTelemetry 标准导出器：

```text
POST http://<host>:8080/v1/logs
Authorization: Bearer lp_xxxxxxxx
Content-Type: application/x-protobuf   # 默认；JSON 编码请用 application/json
```

- 支持 **Protobuf（默认）** 与 **JSON** 两种编码，由 `Content-Type` 判断；
- 支持 `Content-Encoding: gzip`；
- 用环境变量接入（以 .NET/Java/Python 等 OTEL SDK 为例）：

```text
OTEL_EXPORTER_OTLP_LOGS_ENDPOINT=http://<host>:8080/v1/logs
OTEL_EXPORTER_OTLP_LOGS_PROTOCOL=http/protobuf
OTEL_EXPORTER_OTLP_HEADERS=Authorization=Bearer lp_xxxxxxxx
```

各语言最小示例见仓库 `examples/`（`dotnet-console-ingest`、`java-ingest`、`python-ingest`）。

### 5.2 HTTP JSON 批量（辅助入口，调试最方便）

```bash
curl -sS -X POST "http://127.0.0.1:8080/api/v1/ingest/logs" \
  -H "Authorization: Bearer lp_xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "logs": [
      {
        "timestamp": "2026-10-17T10:00:00Z",
        "serviceName": "demo-api",
        "environment": "dev",
        "level": "Error",
        "message": "Database timeout",
        "traceId": "4bf92f3577b34da6a3ce929d0e0e4736",
        "attributes": { "module": "SmokeTest" }
      }
    ]
  }'
```

可复用示例请求体见 `examples/curl-json/sample.json`。

**请求体字段（每一条日志）：**

| 字段 | 说明 |
|---|---|
| `timestamp` | 事件时间（ISO 8601，UTC 建议带 `Z`）|
| `serviceName` | 服务名，检索/告警按此筛选 |
| `environment` | 环境（如 dev / test / prod）|
| `level` | 级别：Trace/Debug/Info/Warn/Error/Fatal |
| `message` | 日志正文 |
| `traceId` / `spanId` | 链路标识，用于串联 |
| `hostName` | 主机名 |
| `exceptionType` / `exceptionMessage` / `exceptionStackTrace` | 异常信息（异常聚合会用到）|
| `eventId` | 事件 ID |
| `attributes` | 自定义键值对 |

**限额（可在配置中调整）：**

| 项 | 默认 |
|---|---|
| 单批条数 `Ingestion:MaxBatchRecords` | 500 |
| JSON 请求体 `Ingestion:MaxBodyBytes` | 1 MB |
| OTLP 请求体 | 8 MB |
| 单条大小 `Ingestion:MaxRecordBytes` | 64 KB |
| 自定义属性个数 `Ingestion:MaxAttributes` | 64 |

**返回：**

```json
{ "requestId": "...", "accepted": 1, "rejected": 0, "status": "ok", "errors": [] }
```

`rejected > 0` 时 `errors[]` 会按索引给出被拒原因。

### 5.3 写入失败不会「假成功」

如果 VictoriaLogs 不可用或写入报错，LogPilot 会返回错误（而不是假装成功），失败次数与丢失条数会记入健康检查与系统设置页（见第 9 节）。

## 6. 日志检索与实时跟随

进入左侧导航「**日志检索**」。

### 6.1 时间窗

时间窗提供四个快捷按钮：**最近 15 分钟 / 最近 1 小时 / 最近 24 小时 / 自定义**。下方灰字会显示本次查询的具体时间范围（按本机时区展示）。

- 前三个是「相对当前时刻」的滚动窗口；
- 「**自定义**」会展开「开始时间 / 结束时间」两个时间选择框（精确到秒），选好后点「**应用时间**」即按该绝对区间查询，可用来翻查任意历史时段。

> 单次查询的时间跨度**不受限制**（`Query:DefaultRangeMinutes` 仅决定默认值，默认 15 分钟）。能翻到多久以前的日志取决于 VictoriaLogs 的保留期（`VICTORIALOGS_RETENTION`，默认 `7d`），超出保留期的历史数据无法再查。

### 6.2 筛选条件

| 条件 | 说明 |
|---|---|
| 项目 | 必选；切换项目会刷新「服务 / 级别」候选 |
| 服务 | 从当前时间窗内出现过的服务里选 |
| 级别 | 从当前时间窗内出现过的级别里选 |
| 关键词 | 匹配消息 / 异常内容 |
| TraceId | 精确匹配链路 |

填好点「**查询**」（关键词、TraceId 支持回车直接查）；「**重置**」回到默认 15 分钟、清空所有筛选并立即查询。

### 6.3 结果与详情

- 结果表按时间倒序；右上角可切换**每页条数**（20 / 50 / 100，默认 50），列表底部用「**上一页 / 下一页**」按页码翻页，并显示「第 N / M 页」与「共 N 条 · 本页显示第 a-b 条」；
- **点击任意一行**打开右侧「日志详情」抽屉，包含：事件 ID、级别、事件时间、接收时间、服务、环境、TraceId、SpanId、消息正文、异常（类型/消息/堆栈）、自定义属性；
- 抽屉内提供「复制消息 / 复制 TraceId / 复制 JSON」三个快捷按钮。

### 6.4 实时跟随（SSE）

点「**● 实时**」按钮，页面通过 Server-Sent Events 订阅 VictoriaLogs 的实时流，新日志会**从顶部逐条插入**（最多保留 500 行）：

- 实时查询条件沿用当前的 服务 / 级别 / 关键词；
- 「**暂停**」会停止渲染但继续接收（缓存），点「继续」一次性补上；
- 再次点按钮（此时显示「■ 停止」）结束订阅；
- **权限变更会立即生效**：连接建立后服务端会周期性复核你的项目权限，一旦你被移出当前项目，连接会以「实时连接已终止」提示并停止推送，不会继续输出该项目日志；
- 若只是网络抖动导致的「实时连接中断」，浏览器会自动重连。

> 部署在 Nginx 等反向代理后面时，需关闭对 `text/event-stream` 的响应缓冲，否则实时推送会延迟（后端已发送 `X-Accel-Buffering: no`）。

### 6.5 用 URL 直达

检索页支持参数，便于从别处（如总览页）带条件跳转：

```text
/logs?projectId=1&range=60&service=demo-api&level=Error&keyword=timeout&traceId=xxx&auto=1
```

`range` 取 `15` / `60` / `1440`；`auto=1` 表示打开即自动执行一次查询。

## 7. 总览页

进入左侧导航「**总览**」。先在上方下拉里选项目，以下内容随项目加载。

### 7.1 组件健康

顶部卡片展示四个组件的实时状态：

| 组件 | 含义 |
|---|---|
| LogPilot Server | 管理服务自身 |
| VictoriaLogs | 日志引擎连通性 + 写入情况 |
| SQLite | 元数据库可读写 |
| 告警评估引擎 | 告警轮询任务是否存活 |

绿色「● 可用」为正常；若显示降级/不可用，会附带 detail 说明（例如 VictoriaLogs 的写入统计与最近一次失败原因）。

### 7.2 KPI

| 指标 | 含义 |
|---|---|
| 日志总数 | 当前时间窗内日志条数 |
| 错误日志 | ERROR / FATAL 条数 |
| 接入服务 | 出现过的服务数量 |

### 7.3 趋势图

柱状图展示最近 12 个 5 分钟时段的「全部日志 / 错误日志」对比，鼠标悬停可看具体数值。

### 7.4 异常聚合

把时间窗内的错误按**指纹**（对消息做归一化后取哈希）归并为「问题」，同类报错只占一行：

| 列 | 说明 |
|---|---|
| 问题 | 归并后的代表标题 |
| 服务 / 级别 | 来源 |
| 次数 | 该指纹在窗口内的出现次数 |
| 首次 / 最近 | 首末出现时间 |

### 7.5 最近错误

列出近 15 分钟内的 ERROR / FATAL（最多 10 条），点击任意一行会跳到日志检索页查看全部。

## 8. 告警中心

进入左侧导航「**告警中心**」。先在上方下拉里选项目。页面分三个标签页。

> 告警评估引擎是进程内的后台任务，**默认每 30 秒**轮询一次规则。

### 8.1 通知渠道（先配渠道，规则里才能选）

「**通知渠道**」标签页 →「**+ 新建渠道**」：

| 类型 | 必填 / 选填字段 |
|---|---|
| **钉钉** | Webhook URL *；加签密钥（可选）|
| **企业微信** | Webhook URL * |
| **邮件** | SMTP 主机 *、端口（默认 587）、用户名、密码、发件人、SSL（是/否）、收件人 *（多个用逗号分隔）|
| **Webhook** | URL *；Headers（JSON，可选）|

保存后可在列表点「**测试**」发一条测试消息验证连通性；点「编辑」修改（**为安全起见密钥不会回填，需重新输入**）；点「删除」移除。

> 渠道配置（Webhook URL、SMTP 密码等）在数据库中是**加密存储**的，列表里只显示脱敏摘要。

### 8.2 告警规则

「**告警规则**」标签页 →「**+ 新建规则**」：

| 字段 | 说明 |
|---|---|
| 规则名称 * | |
| 服务名 | 留空 = 所有服务 |
| 严重级别 | P2 / P1 / P0 |
| 日志级别 | 逗号分隔，例如 `ERROR,FATAL` |
| 关键词 | 例如 `timeout` |
| **条件类型** | **日志条数（Count）** 或 **错误占比（Ratio）** |
| 阈值 * | Count：条数；Ratio：错误占比百分比（1~100）|
| 时间窗口 * | 分钟，最大 1440 |
| 冷却时间 | 分钟，默认 5（同规则两次通知的最小间隔）|
| 重发间隔 | 分钟，留空 = 不重发 |
| 通知渠道 * | 至少勾选一个（仅「启用」状态的渠道可选）|
| 启用 | 启用 / 停用 |
| 恢复时发送通知 | 勾选后，条件恢复时会再发一条恢复通知 |

**Ratio（占比）说明**：统计窗口内「命中条件的错误数 ÷ 同服务范围总日志数 × 100」，达到阈值即触发，适合「错误率飙升」这类场景。

规则列表每行操作：

- **编辑**：修改上述字段；
- **静默**：弹窗输入分钟数（默认 60），期间该规则不发送任何通知，命中的事件会被标记为「已静默」；
- **取消静默**：立即恢复通知；
- **删除**：确认后移除规则。

### 8.3 告警事件

「**告警事件**」标签页展示规则命中的记录，可按状态筛选：

| 状态 | 含义 |
|---|---|
| 触发中（firing） | 条件成立、已通知 |
| 已确认（acknowledged） | 人工点了「确认」，表示已知悉 |
| 已恢复（resolved） | 条件已不成立 |
| 已静默（silenced） | 命中时规则处于静默期，未通知 |

每行展示 状态 / 级别 / 标题 / 触发时间 / 通知次数，并提供「确认」「恢复」两个操作（已恢复的事件不再显示操作）。可「刷新」或「加载更早」翻页。

## 9. 系统设置（写入诊断）

进入左侧导航「**系统设置**」。页面为只读诊断，不展示敏感配置：

- **部署信息**：管理服务、系统数据库、日志引擎、容器数量、健康端点；
- **日志写入诊断**（自本次启动以来累计，**重启后归零**）：

| 指标 | 说明 |
|---|---|
| 写入批次 | 成功 / 总批次数 |
| 写入失败 | 失败次数 + 丢失日志条数 |
| 连续失败 | 当前连续失败次数 |
| 最近失败时间 / 原因 | 定位写入故障的直接线索 |

当**连续写入失败达到 3 次**时，VictoriaLogs 的健康状态会从「可用」降为「降级」，`/health/ready` 返回 503——这样即使 VictoriaLogs 端口仍可连通（但磁盘满、限流或 insert 报 5xx），也能被探针和总览页及时反映出来。

## 10. 排障速查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 写入返回 401 | Token 错误 / 已撤销 / 项目被停用 | 到接入中心确认或重新生成 Token |
| 写入返回 413 | 请求体或单条超限 | 拆分批次；或调大 `Ingestion:MaxBatchRecords` / `MaxBodyBytes` |
| 检索查不到日志 | 时间窗太窄 / 服务或级别筛选过严 / 项目选错 | 放宽时间窗、清空筛选后重查 |
| `/health/ready` 返回 503 | VictoriaLogs 不可达，或连续写入失败 ≥3 | 检查 VL 是否启动、地址 `Storage__VictoriaLogs__BaseUrl`；看系统设置页的失败原因 |
| 总览 KPI / 趋势为空 | 当前项目在时间窗内没有日志 | 确认写入是否成功、服务名与项目是否匹配 |
| 实时跟随不推送 | 反向代理缓冲了 SSE | 关闭代理对 `text/event-stream` 的缓冲 |
| 实时提示「连接已终止」 | 你的账号被移出该项目 / 项目权限被回收 | 到「人员管理 → 项目授权」重新授权后再点「● 实时」|
| 邮件渠道测试失败 | SMTP 主机/端口/SSL/收件人配置有误 | 逐项核对渠道配置，注意端口与 SSL 搭配 |
| 告警一直不触发 | 规则被停用 / 处于静默期 / 阈值或窗口不合适 | 检查规则状态与静默时间，必要时放宽阈值 |

## 11. 一次完整演练（验收清单）

按顺序走一遍，即可确认整条链路可用：

1. 启动后打开 `http://localhost:8080`，完成 `/setup` 创建管理员；
2. 「项目管理」新建项目（例如 `demo` / 编码 `demo`）；
3. 「接入中心」生成 Token，复制保存；
4. 用 `examples/curl-json` 发一条测试日志，应返回 `accepted >= 1`；
5. 「日志检索」选该项目、最近 15 分钟，能查到刚才那条；
6. 点「● 实时」再发几条，能实时从顶部出现；
7. 「总览」能看到健康卡片全绿、KPI 与趋势有数据；
8. 「告警中心」建一个通知渠道并「测试」成功，再建规则（如 ERROR ≥ 3 / 5 分钟）指向该渠道；
9. 停掉 VictoriaLogs 后再写入，确认**不会假成功**（返回错误），且「系统设置」的写入诊断出现失败记录、`/health/ready` 转为 503；
10. 重启 LogPilot，账号、项目、Token、规则仍在。

## 12. 人员管理

「**人员管理**」入口在左侧导航，**只有系统管理员能看到**。非系统管理员直接访问 `/users` 会被拒绝（未登录跳登录页）。

进入后是用户列表，每行展示：用户名、显示名、角色（系统管理员 / 普通用户）、状态（启用 / 停用）、最近登录时间；顶部可按用户名或显示名搜索，底部分页。

### 12.1 新建用户

1. 点右上角「**+ 新建用户**」展开表单；
2. 填写：
   - **用户名** *：3–64 位，只能包含字母、数字、下划线、点或短横线；
   - **显示名**：可留空，留空时与用户名相同；
   - **初始密码** *：8–128 位；
   - **设为系统管理员**：勾选后该用户可管理全部项目与人员；
3. 点「创建」，提示「用户已创建」，列表随即刷新。

### 12.2 停用 / 启用账号

- 行内点「**停用**」，确认后该账号**立即无法登录**；
- 被停用用户**已登录的会话在下一次请求即失效**并跳回登录页（详见第 16 节）；
- 点「**启用**」可恢复被停用的账号；
- **不能停用你自己当前登录的账号**，该行「停用」按钮为禁用态。

### 12.3 设为 / 取消系统管理员

- 点「**设为管理员**」授予系统管理员权限；
- 点「**取消管理员**」并确认后取消；
- 为防止把系统锁死，**不能取消或停用最后一个处于启用状态的系统管理员**，这类操作会返回冲突错误提示。

### 12.4 重置忘记的密码

- 行内点「**重置密码**」，在弹出的输入框里填新密码（8–128 位）即可为该用户设置新密码；
- 新密码请通过安全渠道告知本人，用户登录后可用「修改密码」再自行更换。

## 13. 按项目分配日志可见性

LogPilot 的日志**按项目隔离**：**用户只能看到自己被授权（成为成员）的项目**。授权有两个入口，效果完全一致。

### 13.1 从「人员管理」为用户勾选项目

1. 进入「**人员管理**」，在目标用户那一行点「**项目授权**」；
2. 右侧抽屉列出**全部项目**，每个项目一个下拉，可选：

| 选项 | 含义 |
|---|---|
| 不授权 | 看不到该项目 |
| 只读（viewer） | 仅可查看项目日志 |
| 管理员（admin） | 可查看日志，并可管理该项目的 API Key / 应用 |
| 负责人（owner） | 同管理员，代表项目负责人 |

3. 选好后点「**保存授权**」。保存是**整体替换**：没选中的项目会被取消授权。

### 13.2 从「项目管理」按项目管理成员

「**项目管理**」列表中每个项目有一列「**成员**」，显示成员数量；**系统管理员**可点行内「**成员**」按钮打开抽屉：

- 列出成员（用户名 / 显示名 / 角色），可直接改角色下拉或点「**移除**」；
- 在「添加成员」区选择用户与角色后点「**添加**」。

> 新项目创建后成员数为 **0**，即**创建者不会自动成为项目成员**，需要手动把自己或其他用户加进去。

### 13.3 未授权会怎样

- 普通用户的项目列表只显示自己有权限的项目，看不到未授权项目的任何日志或服务名；
- 未授权却直接请求该项目相关接口（如 API Key、日志查询）会被拒绝，返回 **403**。

## 14. 修改自己的密码

1. 点击页面右上角（账号显示名旁）的「**修改密码**」；
2. 在抽屉里填写：**原密码**、**新密码（8–128 位）**、**确认新密码**；
3. 两次新密码不一致会即时提示；点「**保存**」提交；
4. 原密码正确即提示「密码已更新」并关闭抽屉；**原密码错误会返回 400**，抽屉内显示错误提示，可重新输入。

## 15. 角色与权限速查

| 角色 | 判定 | 能做什么 |
|---|---|---|
| **系统管理员** | `lp_user.is_system_admin = 1` | 访问全部项目；独占「人员管理」页与项目成员配置；可创建项目 |
| **项目负责人（owner）** | 项目成员，角色 owner | 查看该项目日志；管理该项目的 API Key / 应用 |
| **项目管理员（admin）** | 项目成员，角色 admin | 查看该项目日志；管理该项目的 API Key / 应用 |
| **项目只读成员（viewer）** | 项目成员，角色 viewer | 仅查看该项目日志 |

> 普通用户的项目列表只显示自己作为成员的项目；系统管理员的项目列表显示全部项目。

## 16. 常见问题

**Q：为什么某个用户看不到某个项目？**
A：该用户不是这个项目的成员（未授权该用户）。到「人员管理 → 项目授权」，或在「项目管理 → 成员」抽屉里为他授权 / 添加即可。

**Q：为什么刚改完权限就立刻生效了？**
A：系统在**每个请求**都会回查一次用户状态与角色，所以停用账号、管理员升降级、成员增删都**无需重新登录，下一次请求即生效**。

**Q：为什么把最后一个系统管理员的权限取消不掉？**
A：这是**防自锁保护**。系统不允许停用或取消「最后一个处于启用状态的系统管理员」，否则将无人能再管理系统；这类操作会被拒绝并提示冲突。

**Q：管理员停用账号后，该用户多久失效？**
A：**立即**。被停用账号的已登录会话在下一次请求（页面跳转或接口调用）时即失效，会跳回登录页或返回 401，不必等会话 Cookie（7 天）到期。
