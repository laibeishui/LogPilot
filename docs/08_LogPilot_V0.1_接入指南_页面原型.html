接入指南：从零到看到第一条日志

按顺序走完下面六步即可。第 3 步按你项目的语言选择对应标签页，复制代码即可用；页面里所有代码块都会跟随上方「服务地址 / 接入 Token」自动替换。

页面原型 · 可交互
1

建项目

项目管理 → 新建项目，拿到项目编码

2

发 Token

接入中心生成 lp_ 开头的接入密钥

3

接入

按语言配置 SDK / 采集器，指向接入地址

4

自测

发一条日志，确认返回 200 / accepted

5

核对

日志检索里按项目 + 服务名看到它

6

配告警

对 Error 数量或 Error 占比建规则

① 先填这两个值

下面所有代码块都会自动套用，改完直接复制即可。

主入口 · OTLP/HTTP（推荐）
{{HOST}}/v1/logs
辅助入口 · HTTP JSON 批量（调试最方便）
{{HOST}}/api/v1/ingest/logs
自检 · 就绪探针（不用 Token）
{{HOST}}/health/ready
两种入口怎么选 能用 OpenTelemetry SDK / Agent 的（.NET、Java、Python、Node.js、Go）走 OTLP，链路 TraceId、异常堆栈等会自动带上； PHP、脚本、老系统或不想引 SDK 的，走 HTTP JSON 批量入口，20 行代码就能接上。

② 建项目

项目是数据隔离的最小单位：日志、Token、告警都挂在项目下。

  • 左侧「项目管理」→ 右上角「+ 新建项目」
  • 填项目名称、项目编码（英文短标识，如 hilink）、说明可留空
  • 创建成功后状态为「启用」。停用会立刻让该项目下所有 Token 无法写入
一个环境一个项目 建议 dev / test / prod 分开建项目，日志互不干扰，权限也能按项目分配。

③ 生成接入 Token

Token 决定日志写进哪个项目，请求里自带的 projectId 会被忽略。

  • 左侧「接入中心」（或从项目列表点「接入」直接带项目跳过来）
  • 选项目 → 填密钥名称（如 api-prod）→「生成 Token」
  • 明文形如 lp_xxxxxxxx，只显示这一次，请立刻复制保存
  • 数据库只存哈希，关闭页面后无法再查看；建议按环境发独立 Token 便于单独撤销

④ 按语言接入

选择你项目的技术栈，照着配置即可。推荐 OTLP 表示该语言优先走标准 OTLP 入口。

.NET / C# 推荐 OTLP

Web、Worker、控制台都适用；日志级别、TraceId、异常堆栈由 SDK 自动带上。

1) 装包

终端
dotnet add package OpenTelemetry.Extensions.Hosting
dotnet add package OpenTelemetry.Exporter.OpenTelemetryProtocol

2) 注册日志导出（Program.cs）

Program.cs
using OpenTelemetry.Logs;
using OpenTelemetry.Resources;

builder.Logging.AddOpenTelemetry(o =>
{
    // service.name → LogPilot 的「服务」；deployment.environment.name → 「环境」
    o.SetResourceBuilder(ResourceBuilder.CreateDefault()
        .AddService("order-service")
        .AddAttributes(new Dictionary<string, object>
        {
            ["deployment.environment.name"] = "prod"
        }));

    o.IncludeScopes = true;              // 作用域字段会变成自定义属性
    o.IncludeFormattedMessage = true;    // 消息保留占位符替换后的文本

    o.AddOtlpExporter(e =>
    {
        e.Endpoint = new Uri("{{HOST}}/v1/logs");
        e.Protocol = OtlpExportProtocol.HttpProtobuf;
        e.Headers = "Authorization=Bearer {{TOKEN}}";
    });
});

app.Run();
不想写代码？用环境变量全局生效 保留 o.AddOtlpExporter(); 空参调用，然后设置下面四个环境变量，SDK 会自动读取，容器里改起来更方便。
环境变量
OTEL_EXPORTER_OTLP_LOGS_ENDPOINT={{HOST}}/v1/logs
OTEL_EXPORTER_OTLP_LOGS_PROTOCOL=http/protobuf
OTEL_EXPORTER_OTLP_LOGS_HEADERS=Authorization=Bearer {{TOKEN}}
OTEL_RESOURCE_ATTRIBUTES=service.name=order-service,deployment.environment.name=prod

3) 发一条测试日志

任意类 / 接口
logger.LogInformation("用户登录成功，用户ID={UserId}", 10086);
logger.LogError(ex, "处理订单失败，订单号={OrderNo}", "SO202610170001");
不引 SDK 的备选：HTTP JSON 老项目或只想加一行上报时，直接 POST JSON 入口，字段与 examples/dotnet-console-ingest 完全一致。

Java / Spring Boot 推荐 OTLP

有两种接法：Java Agent（零代码，改启动参数即可）和 SDK 手工配置（可控性更强）。

方案 A：Java Agent（零代码，推荐先试）

下载探针
curl -L -o opentelemetry-javaagent.jar \
  https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/latest/download/opentelemetry-javaagent.jar
启动参数
java -javaagent:opentelemetry-javaagent.jar \
  -Dotel.service.name=order-service \
  -Dotel.resource.attributes=deployment.environment.name=prod \
  -Dotel.logs.exporter=otlp \
  -Dotel.exporter.otlp.protocol=http/protobuf \
  -Dotel.exporter.otlp.endpoint={{HOST}} \
  -Dotel.exporter.otlp.headers="Authorization=Bearer {{TOKEN}}" \
  -jar app.jar
最容易踩的坑：endpoint 要不要带 /v1/logs Agent 用 otel.exporter.otlp.endpoint 时填基础地址（{{HOST}}），它会自己补 /v1/logs； 如果你用的是某个 SDK 的 仅日志 endpoint 参数，则要填完整路径 {{HOST}}/v1/logs。填重了会变成 /v1/logs/v1/logs，现象是 400。

方案 B：SDK 手工配置（Spring Boot）

pom.xml
<dependency>
  <groupId>io.opentelemetry</groupId>
  <artifactId>opentelemetry-exporter-otlp</artifactId>
  <version>1.43.0</version>
</dependency>
application.yml
otel:
  logs:
    exporter: otlp
  exporter:
    otlp:
      protocol: http/protobuf
      endpoint: {{HOST}}/v1/logs        # 日志专用 endpoint 用完整路径
      headers:
        Authorization: Bearer {{TOKEN}}
  resource:
    attributes:
      service.name: order-service
      deployment.environment.name: prod

JDK 11+ 自带 HttpClient，无需任何第三方依赖，可直接跑 examples/java-ingest/IngestDemo.java。

Python 推荐 OTLP

标准 logging 模块挂一个 Handler 就能转发，业务代码不用改。

1) 装包

终端
pip install opentelemetry-sdk opentelemetry-exporter-otlp-proto-http

2) 初始化并挂到 logging（app.py）

app.py
import logging

from opentelemetry import _logs
from opentelemetry.exporter.otlp.proto.http._log_exporter import OTLPLogExporter
from opentelemetry.sdk._logs import LoggerProvider, LoggingHandler
from opentelemetry.sdk._logs.export import BatchLogRecordProcessor
from opentelemetry.sdk.resources import Resource, SERVICE_NAME

resource = Resource.create({
    SERVICE_NAME: "order-service",                  # → 服务
    "deployment.environment.name": "prod",          # → 环境
})

provider = LoggerProvider(resource=resource)
provider.add_log_record_processor(BatchLogRecordProcessor(
    OTLPLogExporter(
        endpoint="{{HOST}}/v1/logs",                # 日志专用 endpoint 用完整路径
        headers={"Authorization": "Bearer {{TOKEN}}"},
    )
))
_logs.set_logger_provider(provider)

# 业务代码继续用标准 logging，什么都不用改
logging.basicConfig(
    level=logging.INFO,
    handlers=[LoggingHandler(level=logging.INFO, logger_provider=provider)],
)

log = logging.getLogger("order")
log.info("订单支付完成，订单号=%s", "SO202610170001")
log.error("数据库连接超时，已重试 3 次")

provider.shutdown()   # 进程退出前务必 flush，否则最后一批日志会丢
更省事：零代码自动注入 装 opentelemetry-instrumentation 后，不改一行业务代码：
终端
export OTEL_EXPORTER_OTLP_LOGS_ENDPOINT={{HOST}}/v1/logs
export OTEL_EXPORTER_OTLP_LOGS_HEADERS="Authorization=Bearer {{TOKEN}}"
export OTEL_RESOURCE_ATTRIBUTES="service.name=order-service,deployment.environment.name=prod"

opentelemetry-instrument --traces_exporter none python app.py

Node.js 推荐 OTLP

Node 端没有全局 logging 标准，推荐在启动最前面初始化 OTel，再把它接给 pino / winston。

1) 装包

终端
npm i @opentelemetry/api-logs @opentelemetry/sdk-logs @opentelemetry/resources @opentelemetry/exporter-logs-otlp-http

2) 初始化（telemetry.js，必须最先加载）

telemetry.js
const { logs } = require('@opentelemetry/api-logs');
const { LoggerProvider, BatchLogRecordProcessor } = require('@opentelemetry/sdk-logs');
const { OTLPLogExporter } = require('@opentelemetry/exporter-logs-otlp-http');
const { resourceFromAttributes } = require('@opentelemetry/resources');

const resource = resourceFromAttributes({
  'service.name': 'order-service',                // → 服务
  'deployment.environment.name': 'prod',          // → 环境
});

const provider = new LoggerProvider({
  resource,
  processors: [
    new BatchLogRecordProcessor({
      exporter: new OTLPLogExporter({
        url: '{{HOST}}/v1/logs',                  // 日志专用 URL 用完整路径
        headers: { Authorization: 'Bearer {{TOKEN}}' },
      }),
    }),
  ],
});

logs.setGlobalLoggerProvider(provider);
module.exports = { provider };
app.js
const { provider } = require('./telemetry');   // 第一行
const { logs } = require('@opentelemetry/api-logs');
const logger = logs.getLogger('order');

logger.emit({ severityText: 'ERROR', body: '数据库连接超时', attributes: { orderNo: 'SO202610170001' } });

process.on('SIGTERM', async () => { await provider.shutdown(); process.exit(0); });
用 pino / winston 也行 用 @opentelemetry/winston-transport 或给 pino 加一个 transport， 把 service.name 与 deployment.environment.name 放到 resource 上即可，字段映射规则不变。
进程退出会丢最后一批日志 批量导出是异步的，务必在退出钩子里 await provider.shutdown() 或 forceFlush()， Serverless（函数计算）环境尤其要注意。

Go 推荐 OTLP

Go 1.21+ 用标准库 log/slog，把它桥接到 OTel 即可。

1) 装包

终端
go get go.opentelemetry.io/otel/exporters/otlp/otlplog/otlploghttp
go get go.opentelemetry.io/otel/sdk/log
go get go.opentelemetry.io/contrib/bridges/otelslog

2) 初始化

main.go
ctx := context.Background()

res := resource.NewWithAttributes(
    semconv.SchemaURL,
    semconv.ServiceName("order-service"),                               // → 服务
    attribute.String("deployment.environment.name", "prod"),            // → 环境
)

exp, err := otlploghttp.New(ctx,
    otlploghttp.WithEndpointURL("{{HOST}}/v1/logs"),
    otlploghttp.WithHeaders(map[string]string{"Authorization": "Bearer {{TOKEN}}"}),
)
if err != nil {
    panic(err)
}

lp := log.NewLoggerProvider(
    log.WithResource(res),
    log.WithProcessor(log.NewBatchProcessor(exp)),
)
defer lp.Shutdown(ctx)     // 退出前 flush

slog.SetDefault(slog.New(otelslog.NewHandler("order", otelslog.WithLoggerProvider(lp))))

slog.Error("数据库连接超时", "orderNo", "SO202610170001")
也可以纯环境变量 用 otlploghttp.New(ctx) 空参构造，然后设置 OTEL_EXPORTER_OTLP_LOGS_ENDPOINT / OTEL_EXPORTER_OTLP_LOGS_HEADERS / OTEL_RESOURCE_ATTRIBUTES 三个变量即可。

PHP 走 HTTP JSON

PHP 生态的 OTLP 日志支持较弱，推荐用 Monolog 自定义 Handler 直发 JSON 批量入口，稳定且好排查。

1) 装包

终端
composer require monolog/monolog

2) 自定义 Handler

LogPilotHandler.php
<?php

use Monolog\Handler\AbstractProcessingHandler;
use Monolog\Level;
use Monolog\LogRecord;

final class LogPilotHandler extends AbstractProcessingHandler
{
    public function __construct(
        private string $endpoint,
        private string $token,
        private string $service = 'order-service',
        private string $environment = 'prod',
        Level $level = Level::Debug,
    ) {
        parent::__construct($level);
    }

    protected function write(LogRecord $record): void
    {
        $payload = ['logs' => [[
            'timestamp'   => $record->datetime->format('Y-m-d\TH:i:s.v\Z'),
            'serviceName' => $this->service,
            'environment' => $this->environment,
            'level'       => $record->level->getName(),   // Warning / Error / ...
            'message'     => $record->message,
            'attributes'  => $record->context,          // 注意：context 值会被转成属性
        ]]];

        $ch = curl_init($this->endpoint);
        curl_setopt_array($ch, [
            CURLOPT_POST           => true,
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_TIMEOUT        => 5,
            CURLOPT_HTTPHEADER     => [
                'Authorization: Bearer ' . $this->token,
                'Content-Type: application/json',
            ],
            CURLOPT_POSTFIELDS     => json_encode($payload, JSON_UNESCAPED_UNICODE),
        ]);
        curl_exec($ch);
        curl_close($ch);
    }
}

3) 接入业务

bootstrap.php
$logger = new Monolog\Logger('order');
$logger->pushHandler(new LogPilotHandler(
    endpoint: '{{HOST}}/api/v1/ingest/logs',
    token: '{{TOKEN}}',
    service: 'order-service',
    environment: 'prod',
));

$logger->error('数据库连接超时', ['orderNo' => 'SO202610170001']);
建议：加个批量缓冲 高流量下每条日志一次 curl 开销偏大，可以用 Monolog\Handler\BufferHandler 包一层， 攒到 200 条或 2 秒再发一次（单批上限见下方限额表）。

PowerShell 版本（Windows 服务器常用）

PowerShell
$body = @{
  logs = @(@{
    timestamp   = (Get-Date).ToUniversalTime().ToString("o")

采集器 / 无侵入接入 走 HTTP JSON

不适合改代码的场景：容器 stdout、Nginx 访问日志、Windows 事件日志 —— 交给采集器转发。

Docker 容器 stdout：Vector

vector.toml
[sources.docker_logs]
type = "docker_logs"

[transforms.to_logpilot]
type = "remap"
inputs = ["docker_logs"]
source = '''
.hostName = .container_name
.serviceName = .container_name
.environment = "prod"
.level = upcase(.level) ?? "INFO"
.timestamp = .timestamp
._msg = .message
'''

[sinks.logpilot]
type = "http"
inputs = ["to_logpilot"]
uri = "{{HOST}}/api/v1/ingest/logs"
method = "post"
encoding.codec = "json"
request.headers.Authorization = "Bearer {{TOKEN}}"
request.headers.Content-Type = "application/json"

注意：JSON 入口的请求体必须是 {"logs":[...]}，可用 Vector 的 encoding 模板或 add_fields 把数组包一层；简单起见也可以让采集器直接打 logs 字段。

Nginx 访问日志：Fluent Bit

fluent-bit.conf
[INPUT]
    Name        tail
    Path        /var/log/nginx/access.log
    Tag         nginx.access

[FILTER]
    Name        modify
    Match       nginx.*
    Add         serviceName nginx-gateway
    Add         environment prod

[OUTPUT]
    Name        http
    Match       nginx.*
    Host        logpilot.example.com
    Port        8080
    URI         /api/v1/ingest/logs
    Format      json
    Header      Authorization Bearer {{TOKEN}}

Windows 事件日志 / 本地文件

  • 用 examples/dotnet-console-ingest 里的客户端改造：读文件增量 → 批量 POST，逻辑已可直接复用（支持 --mode json|otlp）
  • 基础设施层（K8s、中间件）一般自带 OTLP 导出，直接填 {{HOST}}/v1/logs 与 Bearer 头即可
  • Nginx 等反向代理转发 /v1/logs 与 /api/v1/ingest 时，请放宽 client_max_body_size（默认 1 MB 会挡掉大包）
反向代理注意两点 一是上面说的请求体上限；二是不要给接入路径开启响应缓冲或重写 Content-Type， OTLP 会按 Content-Type 判断 protobuf / JSON 编码，改错会直接 400。

⑤ 字段怎么落到 LogPilot

OTLP 走标准语义约定，HTTP JSON 走扁平字段，最终映射到同一套模型。

OTLP（资源属性 / 日志属性）HTTP JSON 字段LogPilot 字段说明
service.nameserviceName服务缺失记为 unknown；检索、告警、样本日志都按它筛
deployment.environment.name
deployment.environment		environment环境告警分子/分母统计会同步应用该过滤
host.namehostName主机一般由 SDK 自动带上
SeverityText / SeverityNumberlevel级别归一为 Trace/Debug/Info/Warn/Error/Fatal，兼容 WARNING、CRITICAL、数字等写法
Bodymessage消息JSON 入口必填；单条上限 64 KB

  • 发一条：用上面的 curl 或 SDK，看到 200 / accepted: 1

⑦ 返回码对照与排障

返回含义怎么办
200接收成功JSON 入口再看 rejected 是否为 0
400报文无法解析检查 Content-Type 与实际编码是否一致；endpoint 有没有重复拼 /v1/logs
401Token 缺失 / 无效 / 已撤销，或项目被停用确认 Bearer 前缀、Token 以 lp_ 开头、项目处于启用状态
413超过体积或条数上限拆小批次：单批 ≤ 500 条、JSON ≤ 1 MB
429触发写入限流增大批量、加指数退避；必要时调高每分钟上限
503日志存储暂不可用（可重试）看「系统设置」的写入诊断；SDK 会自动重试
500写入失败连续 3 次失败会让 /health/ready 变 503，任一成功即自愈
日志进去了但「服务」显示 unknown OTLP 路径必须设置 service.name 资源属性（.NET 用 AddService("...")， Java 用 otel.service.name）；JSON 路径则是 serviceName 字段留空了。

⑧ 接完日志之后

日志能稳定写进来就可以继续往下做了。

  • 实时盯着：日志检索页点「● 实时」，新日志从顶部逐条进（掉线浏览器会自动重连；权限被回收时连接会立即终止）
  • 配告警：告警中心 → 新建规则，按「Error 数量 > N」或「Error 占比 > X%」在 5 分钟窗口内判定，渠道支持钉钉 / 企业微信 / 邮件 / Webhook
  • 分权限：人员管理 → 给成员授予某个项目的 viewer / admin，成员登录后只能看到被授权的项目
  • 对外提供：把接入地址与 Token 交给业务方，Token 按环境拆分，出问题单独撤销即可
