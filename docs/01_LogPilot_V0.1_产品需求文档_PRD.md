## 1. 产品概要

### 1.1 产品定位
LogPilot 是一个**轻量化、部署简单化、使用方便化**的跨语言开源、自托管日志中心。面向个人开发者与中小型开发团队，统一收集、检索和管理多个应用的运行日志。数据隐私增强功能当前非差异化重点，但**认证、项目隔离、传输与凭证保护属于不可省略的安全底线**。

### 1.2 核心原则及验收依据
| 原则 | 设计要求 | 验收依据 |
|---|---|---|
| 轻量化 | 不引入 RabbitMQ、Redis、MySQL 或独立前端运行服务 | 运行期仅 LogPilot 和 VictoriaLogs 两个容器 |
| 部署简单 | Docker Compose 一键启动，本地持久化目录、明确升级和备份步骤 | 按 README 在全新环境完成安装与日志首写 |
| 使用方便 | 统一登录、项目、日志查询与接入说明；开箱有示例数据发送命令 | 新用户无需阅读源码即可完成首次接入 |
| 跨语言 | 主要方式 OpenTelemetry SDK + OTLP/HTTP Protobuf，备用 HTTP JSON 批量 | .NET、Java、Python 示例至少各有一条端到端验证 |
| 高频写入 | SDK 异步批量、服务端有界并发、失败反馈 | 压测记录吞吐、P95、CPU/内存及失败情况 |

**资源策略**：不将“2 核 4GB”定义为最低要求或项目唯一目标；将其作为可选择的测试档位之一，实际资源指南以实测为准。

## 2. 用户与使用场景

### 2.1 角色
- **系统管理员**：首次初始化、管理项目与人员、接入 Token、部署设置。
- **项目管理员**：维护本项目服务、创建/撤销项目 Token、查看本项目日志。
- **项目查看者**：仅查询获授权项目日志；不创建密钥、不更改配置。
- **日志生产者**：.NET、Java、Python、Node.js、Go 等业务程序，使用 SDK 或批量 HTTP 写入。

### 2.2 主要场景
1. 应用线上报错：开发者按项目、服务、级别、时间筛选错误并查看堆栈与上下文。
2. 多应用统一管理：管理员为不同项目创建 Token，避免应用之间串数据。
3. 旧系统接入：通过 HTTP JSON 批量发送，复用相同鉴权与字段规范化处理。
4. 开发者快速体验：拉起两个容器，创建项目、复制示例、发送日志、在 Web 页面看到日志。

## 4. 页面与操作流程

### 4.1 导航结构
| 菜单 | V0.1 状态 | 页面关键元素 |
|---|---|---|
| 总览 | 基础版/演示 | 项目选择、连接状态、快捷入口；高级趋势后续 |
| 日志检索 | 必须 | 时间快捷选项、服务、级别、关键词、分页、详情 |
| 项目管理 | 必须 | 项目列表、创建/编辑、停用 |
| 接入中心 | 必须 | OTLP SDK 配置示例、HTTP JSON 示例、Token 管理 |
| 告警中心 | V0.2 实现 | 告警事件列表（状态过滤、确认/恢复）、告警规则 CRUD（匹配范围、计数阈值、时间窗口、通知渠道、冷却/重发）、通知渠道 CRUD（钉钉/企微/邮件/Webhook + 测试发送） |
| 系统设置 | 基础版 | 部署状态与配置说明；高级设置后续 |

### 4.2 首次使用旅程
1. 安装 Docker、Compose，复制 `.env.example` 为 `.env`，配置数据目录、管理员初始化方式及端口。
2. 启动两个容器，进入 LogPilot 初始化页面，创建首个管理员。
3. 创建项目并生成 Token（只显示一次）；选择 SDK 或 HTTP JSON 接入方式。
4. 根据接入中心示例发送测试日志，得到明确成功或可诊断失败响应。
5. 进入日志检索页面，切换到该项目和近 15 分钟，看到对应日志与详情。

### 4.3 日志查询行为
- 默认时间范围：最近 15 分钟。快捷项：15 分钟、1 小时、24 小时；可自定义。
- 查询条件：项目（必选）、服务（可多选或全部）、级别、关键词、TraceId（高级）。
- 列表默认按事件时间降序，单页最多 100 条（前端默认 50；数值可配置）。
- 列表字段：时间、级别、服务、消息摘要、TraceId（可隐藏）。
- 详情显示 JSON 展开、异常堆栈、完整时间、复制按钮。
- 无结果：提示调整时间、筛选项；请求失败：显示可识别错误和重试操作。
- 大范围查询、深分页、复杂匹配在服务端进行限制，不能任意透传原始 LogsQL 给普通用户。
- 数据查询范围由服务端从会话授权项目推导，禁止只信任浏览器传入的 projectId。

## 5. 日志写入与字段规范

### 5.1 主入口：OTLP/HTTP Protobuf
- 地址：`POST /v1/logs`；`Content-Type: application/x-protobuf`。
- 客户端：OpenTelemetry SDK + OTLP exporter + batch processor；常规日志调用不应等待同步网络写入。
- 项目 Token：通过请求头承载，映射到服务端实际项目；服务端覆盖不可信 projectId。
- 标准 OTLP 响应：使用 Protobuf ExportLogsServiceResponse；部分成功需表达 rejectedLogRecords 和原因；错误状态按协议处理。
- SDK 的批量大小、内存队列、重试、压缩能力取决于语言与 SDK 配置；不得宣称所有 SDK 都支持持久化重试。

### 5.2 辅助入口：HTTP JSON 批量
- 地址：`POST /api/v1/ingest/logs`；`Authorization: Bearer <token>`。
- 请求示例：

```json
{
  "logs": [
    {"timestamp":"2026-10-13T10:00:00Z","serviceName":"demo-api","level":"Error","message":"Database timeout","traceId":"abc123"}
  ]
}
```

- 主要用于脚本、老系统与联调。高频生产者必须自行合批与异步处理，不推荐一条日志一个同步 HTTP 请求。
- 响应明确接收、拒绝、失败原因；成功不等于“只放入内存队列”。

### 5.3 统一内部字段
`id`、`projectId`、`timestamp`、`ingestedAt`、`serviceName`、`environment`、`level`、`message`、`traceId`、`spanId`、`exceptionType`、`exceptionMessage`、`exceptionStackTrace`、`attributes`。

VictoriaLogs 负责实际日志数据；SQLite 只保存用户、项目、Token 与管理配置，禁止把海量日志正文写入 SQLite。

## 6. 写入可靠性与非功能要求

| 编号 | 要求 | 设计/测试重点 |
|---|---|---|
| N01 | 业务非阻塞 | 通过 SDK 批量处理，不在业务请求内逐条发送 |
| N02 | 无队列依赖 | 不强制 RabbitMQ/Kafka/Redis；服务端限流和写入超时 |
| N03 | 正确确认 | LogPilot 按 VictoriaLogs API 真实响应确认，严禁“排进内存即成功” |
| N04 | 故障可诊断 | VictoriaLogs 不可用时返回错误，客户端按可重试条件退避 |
| N05 | 上限保护 | 单请求数据量、条数、字段大小、解压后体积、并发均有可配置上限 |
| N06 | 安全底线 | 管理身份验证、项目隔离、Token 哈希、HTTPS 文档、日志内容安全呈现 |
| N07 | 可维护性 | `.NET 8 + MVC/Web API + Razor/Vue 3 + Dapper/SQLite`，模块明确 |
| N08 | 低依赖 | LogPilot 与 VictoriaLogs 双容器，MySQL/Meilisearch 非必需 |
| N09 | 可复现 | 锁定镜像版本和 NuGet/NPM 依赖，提供升级与备份说明 |

**可靠性取舍**：未部署独立持久化消息队列时，LogPilot 不保证所有客户端网络中断都零丢失；应用自身的日志框架、采集器或持久化缓冲需按重要程度设置。运行日志不得取代财务流水和法定审计记录。

## 8. 界面原型说明

交付 `LogPilot_管理后台_交互原型_V0.1.html`。它是一个**离线单文件交互原型**，用于确认页面结构和操作，不与后端交互，也不会保存真实日志或密钥。页面中的趋势、状态、项目、日志以及模拟新增数据属于示例内容。操作包括：侧边菜单切换、日志关键字/级别/服务过滤、时间范围选择、日志详情、模拟新增项目、接入命令切换与复制。

与实际版本的关系：日志检索、项目、接入中心属于 V0.1；高级统计和告警展示属于规划占位，不得作为 V0.1 功能完成证明。

## 10. 非目标、风险与开放问题

- V0.1 **不做**：完整 APM、Metrics 展示、Trace Span 详情、AI 根因分析、OTLP/gRPC、高级告警、多实例 HA。
- VictoriaLogs 日志流/租户标签与项目隔离的字段映射应经集成测试验证，尤其防止通过查询条件绕过隔离。
- SQLite 单实例写入适合当前元数据规模；如未来支持多 LogPilot 实例，需重新评估共享元数据架构。
- 原型为视觉和交互设计，不代表后端、数据库、认证已经实现。
- 项目正式公开前检查许可证、依赖及镜像供应链，并完成基本安全审计。
