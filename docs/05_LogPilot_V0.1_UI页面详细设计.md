## 1. 文档目标及产品原则

本文件把现有 HTML 原型转换为可以开发、联调和验收的页面规范；**不扩大 V0.1 的开发范围**。

产品优先级依次为：**轻量化、部署简单化、使用方便化**。基础的认证、凭证保护和项目隔离属于必要安全要求，但 V0.1 不开发复杂的隐私治理产品。

- 服务器：ASP.NET Core 8 MVC + Web API，同一个 LogPilot 容器承载 Razor 页面、静态资源与脚本和管理 API。
- 数据层：SQLite + Dapper 管理元数据；VictoriaLogs 保存业务日志，作为第二个 Docker 容器。
- 客户端：Razor + 原生 JavaScript 渐进增强，**不强制前端框架**；不要求运行时 Node.js，也不独立部署 SPA 容器。
- 日志发送：OpenTelemetry SDK + OTLP/HTTP Protobuf 为首选；HTTP JSON 批量为辅助。
- 所有用户可见数字、日志、项目、接入状态均必须来自真实接口；演示环境须显著标记“演示数据”。

## 3. 全局布局与视觉规范

### 3.1 页面骨架

- 桌面版：左侧导航约 220–240px；顶部为当前位置、项目切换、账号菜单；右侧内容区最大宽度建议 1500px。
- 移动/窄屏：导航可收起为抽屉；内容可纵向滚动；日志表允许横向滚动或切换卡片展示。
- 首版采用浅色主题，优先清晰度与信息密度，暗色主题可后续添加。
- 使用统一页面标题、说明、副操作区、筛选栏、内容表格、分页及错误提示。
- 按钮：主要动作用实心强调色；危险操作采用确认弹窗；禁用态必须说明原因。

### 3.2 建议设计 Token

| Token | 建议值 | 使用场景 |
|---|---|---|
| 页面背景 | `#F5F7FB` | 主工作区 |
| 内容背景 | `#FFFFFF` | 卡片、表格、对话框 |
| 正文 | `#182339` | 标题与数据 |
| 次级文本 | `#66758A` | 说明、占位 |
| 边框 | `#E7EBF1` | 分隔线 |
| 品牌强调色 | `#496FF5` | 主按钮、选中态 |
| 成功 | `#16A376` | 已连接、正常 |
| 错误 | `#E44D5D` | Error、失败 |
| 警告 | `#D99725` | Warn、风险 |
| 基础圆角 | 8–13px | 按钮和卡片 |

以上色值延续现有 HTML 原型作为建议，不强制使用某套重型前端框架。字体优先系统字体。状态不仅依赖颜色，必须同时展示文字。

### 3.3 组件规范

**通用组件：** `AppShell`、`ProjectSelector`、`PageHeader`、`SearchToolbar`、`StatusBadge`、`LoadingState`、`EmptyState`、`ErrorState`、`ConfirmDialog`、`CopyButton`、`Pagination`、`LogLevelBadge`、`JsonViewer`。

- 加载：筛选切换时应显示局部 loading，保留筛选条件，不应整页白屏。
- 反馈：成功轻提示；失败显示简短错误 + 可操作的重试入口；不要把异常堆栈直接暴露给普通页面。
- 无权限：显示“无权查看该项目”，不泄露项目日志数量或服务名称。
- 文案与时间：中文为默认语言；时间在页面展示为浏览器本地时间，悬停或详情提供 UTC 原始时间。
- 可访问性：按钮可通过键盘操作，输入框有 label，对话框支持 ESC 关闭和焦点管理。

### 3.4 全局顶栏与修改密码抽屉

- 顶栏右侧固定展示：当前位置、当前账号显示名、「修改密码」按钮、「退出」按钮。
- 点「修改密码」从右侧滑出抽屉，字段：原密码、新密码（8–128 位）、确认新密码。
- 两次新密码不一致时前端直接提示、不提交；提交调用 `PUT /api/v1/auth/password`；**原密码错误返回 400**，在抽屉内展示错误提示且不关闭抽屉。
- 每次打开抽屉清空上次输入；修改成功后提示并关闭。修改密码是全局能力，对所有已登录用户可用。

## 4. 页面一：首次初始化与登录

### 4.1 首次初始化 `/setup`

**前提：** SQLite 中还不存在管理员账号。此时仅开放初始化所需路由；创建成功后关闭初始化入口。

页面字段：管理员账号、密码、确认密码。提示密码最小强度要求和数据存储目录是否可写。提交中禁用重复点击。

状态：未初始化 / 初始化中 / 初始化成功 / 失败（已初始化、数据库不可写、请求过期）。服务端必须保证仅能初始化一次，不能仅依赖隐藏按钮。

### 4.2 登录 `/account/login`

字段：账号、密码；功能：登录、错误反馈、退出及登录状态失效跳转。

- 登录失败统一文案，避免泄露账号是否存在。
- Cookie 使用 HttpOnly、SameSite 并在 HTTPS 环境下启用 Secure；表单及敏感管理操作要有 CSRF 防护。
- 已登录用户访问登录页可返回总览；会话失效时提示并跳转。

## 5. 页面二：总览 `/`

**V0.1 只实现轻量总览，不能承诺尚未实现的历史趋势图或告警结果。**

页面内容：

1. 当前项目名称、快速切换入口（无可访问项目则提示创建或联系管理员）。
2. 服务健康卡片：LogPilot API 状态、VictoriaLogs 可连接状态，采样时间。
3. 快捷操作：“查询日志”“创建项目”“配置接入”。
4. 可选小型概览：最近 15 分钟日志条数及 Error 数；如果查询成本高或统计接口未就绪，可以不显示，不能使用假数据。
5. 告警概览入口：告警中心已在 V0.2 实现，总览可展示活跃告警数量或入口；未接入时不得用假数据。

| UI 状态 | 显示行为 |
|---|---|
| 正常 | 绿色连接状态 + 最近检查时间 |
| 数据库不可用 | 明确提示存储不可用，不显示伪正常 |
| 无项目 | 空状态与创建/申请权限指引 |
| 统计超时 | 健康状态和统计分开显示；统计可单独重试 |

关联接口：健康诊断端点、`GET /api/v1/stats/overview`（如实现基础统计）、项目列表。

## 6. 页面三：日志检索 `/logs`

这是 V0.1 最重要的页面，应优先开发。

### 6.1 查询区域

| 控件 | 默认 | 行为 |
|---|---|---|
| 项目 | 最近使用的有权限项目 | 必选；切换后重置分页 |
| 时间 | 最近 15 分钟 | 快捷：15m、1h、24h；可自定义 UTC 区间 |
| 服务 | 全部 | 可选择服务，来源必须受项目权限约束 |
| 级别 | 全部 | Trace/Debug/Info/Warn/Error/Fatal 等标准化显示 |
| 关键词 | 空 | 支持消息与异常内容检索；回车提交 |
| TraceId | 空 | 高级筛选；保留完整精确值 |
| 查询按钮 | 可用 | 显式执行；请求期间禁用重复提交 |
| 重置 | — | 清空筛选，恢复 15m 范围 |

- 项目变更、时间变更、筛选变更时，统一重置分页/游标。
- 关键词不能未经转义直接插入 LogsQL；由服务端进行字段白名单和参数/安全查询构造。
- 禁止普通用户输入任意 LogsQL 后透传到 VictoriaLogs；高级查询功能后续单独评估。
- URL 可以保存非敏感筛选条件以方便分享，但绝不把 Token 放入 URL。

### 6.2 日志列表

建议列：`时间` / `级别` / `服务` / `消息摘要` / `TraceId（可隐藏）` / `详情`。

- 按事件时间降序，默认每页 50 条，上限 100 条。
- 消息单行省略，保留完整内容的详情入口；长堆栈不直接渲染到整行。
- 统一使用本地时间展示，详情提供 UTC 精度。
- 未查到结果：显示搜索条件及“修改时间范围/清除筛选”入口。
- 查询失败：保留上次结果时标明其不是本次最新结果，并提供重试；不能静默展示过期数据。
- 大量日志分页：按 API 文档使用安全游标/时间锚点；如果后端无法保证稳定翻页，限制为“加载更早”而不是承诺任意深度页码。

### 6.3 详情交互

点击行或“详情”，右侧抽屉（桌面）或全屏弹层（移动）显示：

- 事件 ID、事件时间、接收时间（如有）、服务、项目、级别。
- `message` 完整内容与换行保留。
- TraceId、SpanId、异常类型、异常消息、堆栈（字段不存在显示“无”）。
- 自定义属性键值对、原始 JSON（折叠显示，长字段按需展开）。
- “复制消息”“复制 TraceId”“复制 JSON”；复制动作必须反馈成功/失败。

不允许将日志消息作为 HTML 直接插入 DOM，渲染时必须进行文本转义；堆栈、属性等均作为普通文本展示，防止日志内容注入。

### 6.4 查询与详情状态机

```mermaid
graph TD
    A["未查询"] --> B["输入条件"]
    B --> C["加载中"]
    C --> D["有结果"]
    C --> E["无结果"]
    C --> F["查询失败"]
    D --> G["查看详情"]
    E --> B
    F --> B
    G --> D
```

### 6.5 API 对应

- `POST /api/v1/logs/search`：执行搜索。
- `GET /api/v1/logs/{id}`：详情（以 API 03 定义的定位能力为前提）。
- `GET /api/v1/logs/filters`：候选服务、级别。
- `GET /api/v1/logs/context`：如首版实现“查看上下文”，需受时间及数量限制。

## 7. 页面四：项目管理 `/projects`

### 7.1 项目列表

字段：项目名称、唯一编码、成员数、说明、状态、可执行操作。列表不直接展示 Token。

- **成员**列：展示每个项目的成员数（`memberCount`）；新建项目的成员数为 0。
- 操作：创建、成员管理、编辑、停用、前往日志、前往接入中心。其中「新建项目」按钮**仅系统管理员可见**；创建者不会自动成为项目 owner。
- 普通用户的项目列表只显示自己作为成员的项目；系统管理员的项目列表显示全部项目。

### 7.2 创建/编辑

| 字段 | 校验 |
|---|---|
| 名称 | 必填，最大长度按数据库和 API 文档 |
| 编码 | 必填，唯一；建议小写字母、数字和短横线；创建后原则上不可修改 |
| 说明 | 可选，有长度限制 |
| 状态 | 启用/停用；停用需要二次确认 |

停用项目后对应 Token 不可继续写入；既有日志是否仍可按保留策略查看，由后端业务规则控制并在 UI 中明确说明。

普通用户不可编辑无权限项目；按钮隐藏仅是界面优化，服务端必须校验。

### 7.3 项目成员管理（成员列 + 成员抽屉）

- 项目列表的「成员」列展示成员数；**仅系统管理员**可见行内「成员」按钮，点击从右侧打开成员抽屉。
- 成员抽屉内容：
  - 现有成员列表：展示 用户名、显示名、角色；每行提供角色下拉（只读 viewer / 管理员 admin / 负责人 owner）与「移除」按钮，改角色或移除即时生效。
  - 「添加成员」区：从下拉选择用户与角色后点「添加」；无候选用户时禁用添加。
  - 无成员时提示「尚无成员，添加后该用户才能查询本项目日志」。
- 项目成员与人员管理页的「项目授权」抽屉（见第 10 节）是同一份授权的两个入口，效果一致。
- 角色含义：owner（负责人）与 admin（管理员）可查看日志并可管理该项目 API Key / 应用；viewer（只读成员）仅可查看项目日志。
- 对应 API：
  - `GET /api/v1/projects/{id}/members`：列出项目成员。
  - `POST /api/v1/projects/{id}/members`：添加成员或修改成员角色（body：`userId`、`role`）。
  - `DELETE /api/v1/projects/{id}/members/{userId}`：移除成员。

## 8. 页面五：接入中心 `/integrations`

**V0.1 同时支持两条真实接入路径，SDK 是默认首选。**

### 8.1 接入流程

```mermaid
graph TD
    A["选择项目"] --> B["生成 Token"]
    B --> C["只显示一次"]
    C --> D["选择接入方式"]
    D --> E["OpenTelemetry SDK"]
    D --> F["HTTP JSON 批量"]
    E --> G["发送测试日志"]
    F --> G
    G --> H["前往日志检索验证"]
```

### 8.2 Token 设计

- 创建前选择项目及有效期，提交后一次性展示密钥，可复制。
- 提供“我已安全保存”确认；关闭后无法再次显示明文，只可撤销并新建。
- 密钥表格仅显示名称、前缀、创建时间、过期时间、最后使用时间、状态、撤销。
- 不能将 Token 放到 URL、前端持久化存储或客户端日志；复制时不打印控制台。

### 8.3 SDK 接入选项卡

默认选中“OpenTelemetry SDK（推荐）”。提供语言切换：`.NET`、`Java`、`Python`；其他语言提供通用 OTLP 环境变量说明链接/示例。

示例重点：

```text
OTEL_EXPORTER_OTLP_LOGS_ENDPOINT=https://your-host/v1/logs
OTEL_EXPORTER_OTLP_LOGS_PROTOCOL=http/protobuf
```

必须提示：还需要安装/启用对应语言的日志导出器、配置批量处理器和认证 Header。仅设置环境变量不代表 SDK 一定会自动采集日志。Header 格式需按语言 SDK 分别说明。

### 8.4 HTTP JSON 接入选项卡

- 展示 POST 地址、Bearer Token Header、批量 JSON 示例及 cURL 示例。
- 说明由调用方自行实现合批、重试和超时控制，不推荐业务线程逐条同步请求。
- 示例默认使用脱敏假 Token，不能把真实 Token 写入 GitHub 示例。

### 8.5 验证和排障

- 提供“复制测试命令”以及“打开日志检索并带入当前项目/最近 15 分钟”。
- `401`：凭证问题；`403`：项目权限；`413`：请求体过大；`429`：限流；`5xx`：接收端或存储故障。
- OTLP Protobuf 的响应格式与业务 JSON API 不同；页面只能把响应解释为对应协议定义的语义，不能一概提示“HTTP 200 = 所有日志已永久保存”。

## 9. 页面六：系统设置与健康 `/settings`

V0.1 仅提供只读基础诊断及必要配置说明：

- LogPilot 版本、VictoriaLogs 服务可连接性、检测时间。
- SQLite 数据文件/挂载目录的存在性与可写状态（不显示绝对敏感路径或密码）。
- 日志写入失败计数、最近故障概览（**已实现**：批次成功/失败数、连续失败次数、丢失条数、最近失败时间与原因；进程内累计，重启归零）。
- 文档链接、备份与恢复说明、默认保留策略的说明。

实现说明：`/health/ready` 中 `victoriaLogs` 的 `detail` 同样附带写入统计；连续失败达到阈值时该组件降级为 `Degraded`，`/health/ready` 返回 503，任一次写入成功后自动恢复。

VictoriaLogs 的真实保留策略应从实际部署配置读取或明确注明“配置文件声明值”；不要将 UI 表单改动伪装成已即时生效。

## 10. 页面七：人员管理 `/users`

### 10.1 页面目标与进入方式

- 页面目标：为系统管理员提供集中的人员与授权管理入口——创建/停用账号、升降系统管理员、为他人重置密码，以及为用户分配可见项目。
- 进入方式：左侧导航「人员管理」（**仅系统管理员可见**），路由 `GET /users`（控制器 `UsersController`，`[Authorize(Policy = SystemAdmin)]`）。
- 非系统管理员直接访问 `/users` 会被拒绝：未登录跳转登录页；已登录但非管理员返回无权限，且不展示任何用户数据。

### 10.2 页面布局

- 顶部标题区：「人员管理」标题与说明，右侧「+ 新建用户」按钮。
- 新建用户面板（默认隐藏）：用户名、显示名、初始密码、是否系统管理员，以及「创建 / 取消」。
- 搜索栏：按用户名或显示名的关键词搜索（回车或点「查询」触发，关键词变更后回到第 1 页）。
- 用户列表区：表格 + 底部分页（「上一页 / 下一页」及「第 N / M 页 · 共 N 条」）。
- 行操作：项目授权、重置密码、设为/取消管理员、启用/停用。
- 「项目授权」抽屉：从右侧滑出，列出全部项目与角色下拉。

### 10.3 列表字段

| 列名 | 含义 |
|---|---|
| 用户名 | 登录账号，唯一 |
| 显示名 | 展示名称，留空时与用户名相同 |
| 状态 | 启用 / 停用 |
| 是否系统管理员 | 系统管理员 / 普通用户 |
| 创建时间 | 账号创建时间 |
| 最近登录 | 最近一次登录时间，未登录显示「—」 |

### 10.4 交互流程

- **新建用户**：点「+ 新建用户」展开面板，填写用户名（3–64 位字母、数字、下划线、点或短横线）、密码（8–128 位）、显示名（可选，留空同用户名）与是否系统管理员，点「创建」；成功后提示「用户已创建」并刷新列表。
- **启用 / 停用账号**：行内「停用 / 启用」按钮。停用前二次确认；**当前登录账号的「停用」按钮为禁用态，不可点击**。
- **设为 / 取消系统管理员**：行内「设为管理员 / 取消管理员」按钮；取消需二次确认。
- **重置密码**：行内「重置密码」，输入新密码（8–128 位），调用 `POST /api/v1/users/{id}/password`。
- **项目授权**：行内「项目授权」打开抽屉，列出全部项目，每个项目一个下拉「不授权 / 只读（viewer） / 管理员（admin） / 负责人（owner）」；点「保存授权」**整体替换**该用户的项目授权（未选中的项目即被取消授权）。

### 10.5 权限与错误提示

- 只有系统管理员能进入本页；页面展示与接口必须**服务端校验**，不能只依赖导航隐藏。
- 防自锁：不能停用当前登录账号；不能取消或停用**最后一个处于启用状态的系统管理员**，此类操作会被服务端拒绝并在页面提示冲突错误。
- 其余校验（用户名格式、密码长度、用户名重复等）失败时，在页面顶部提示错误文本。

### 10.6 API 对应

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/users` | 用户列表，支持 `page`、`pageSize`、`keyword`；响应含 `total`、`items` |
| POST | `/api/v1/users` | 新建用户（`username`、`displayName`、`password`、`isSystemAdmin`） |
| PATCH | `/api/v1/users/{id}` | 启用/停用（`enabled`）、设为/取消系统管理员（`isSystemAdmin`） |
| POST | `/api/v1/users/{id}/password` | 为指定用户重置密码（`password`） |
| GET | `/api/v1/users/{id}/memberships` | 查询该用户的项目授权 |
| PUT | `/api/v1/users/{id}/memberships` | 整体替换该用户的项目授权 |

### 10.7 权限即时生效

- 账号被停用后，该用户**已登录的会话在下一次请求即失效**：页面跳转登录页、接口返回 401，无需等待会话 Cookie（有效期 7 天）到期。
- 系统管理员的授予或取消在目标用户**当前会话内立即生效**：授予后无需重新登录即可看到「人员管理」导航并访问 `/users`；取消后立即失去该入口与权限。
- 实现上由中间件在每个已认证请求回查一次用户状态并同步角色声明，因此权限变更无需重新登录。

## 11. 告警中心 `/alerts`（V0.2 实现）

告警中心页面采用三 Tab 结构：告警事件、告警规则、通知渠道。

### 11.1 Tab 一：告警事件

- 默认显示当前选中项目下最近的告警事件，按 `last_fired_at` 降序
- 顶部状态过滤：全部 / 触发中(firing) / 已确认(acknowledged) / 已静默(silenced) / 已恢复(resolved)
- 列表字段：状态徽标、严重级别、规则名、摘要、首次触发、最近触发、操作
- 操作：确认（firing→acknowledged）、标记恢复（firing/acknowledged→resolved）
- 分页：基于游标，加载更多

### 11.2 Tab 二：告警规则

- 规则列表：名称、匹配范围（服务/级别/关键词）、条件（类型/阈值/窗口）、冷却、渠道、静默状态、状态开关、操作
- 新建/编辑规则（模态框）：
  - 基础信息：名称、严重级别（P0/P1/P2/P3）、启用
  - 匹配范围：服务名（可选，留空=全部）、日志级别（多选）、关键词（可选）
  - 触发条件：条件类型（`Count` 条数 / `Ratio` 占比）、阈值（Ratio 为 1~100 百分比）、时间窗口（分钟）
  - 通知策略：关联渠道（多选）、冷却时间、重发间隔（可空）、发送恢复通知
- 静默：列表行提供「静默 / 取消静默」操作，静默时填写分钟数；静默期内命中只标记事件、不发送通知
- 删除前二次确认；规则启停即点即存

### 11.3 Tab 三：通知渠道

- 渠道列表：名称、类型图标、脱敏摘要、启用状态、操作（编辑、测试、删除）
- 新建/编辑渠道（模态框）：
  - 名称、类型（钉钉/企微/邮件/Webhook）、启用
  - 配置表单根据类型动态切换字段
  - 编辑时**不回填**密钥等敏感字段，需重新输入（安全考虑）
- 测试发送：向该渠道发送一条测试消息，反馈成功/失败
- 渠道配置（含密钥）在服务端 AES 加密存储，列表只显示脱敏摘要

### 11.4 安全与交互细节

- 所有写操作携带 CSRF Header
- 渠道配置中的密钥字段使用 `type="password"`
- 模态框提交时进行前端校验（必填、URL 格式、端口范围等）
- 列表加载、保存、测试发送均有 loading 与错误提示

## 12. UI 与接口的统一状态和错误规范

| 场景 | 前端处理 | 验收要求 |
|---|---|---|
| 网络超时 | 保留输入，提示超时和重试 | 不误报查询无结果 |
| `401` 未登录 | 返回登录，必要时保留安全的回跳地址 | 不暴露敏感路径 |
| `403` 无权限 | 显示无访问权 | 不展示项目数据 |
| `404` 日志不存在 | 显示日志不存在或已过保留期 | 弹层可关闭 |
| `413` 请求太大 | 接入中心说明缩小批次 | 不无限重试 |
| `429` 请求过多 | 展示限流与 Retry-After（若有） | 不自动造成重试风暴 |
| `5xx` 存储故障 | 提示服务不可用，允许重试 | 不误报成功 |
| 空字段 | 显示“无”或不展示该行 | 页面无脚本异常 |
| 超长日志 | 文本截断展示 + 详情展开 | 不造成布局崩坏 |

## 13. MVC + 原生 JS 实现落地

### 13.1 约定路由

| Razor 页面路由 | 对应模块 |
|---|---|
| `/setup` | 初始化 |
| `/account/login` | 登录 |
| `/` | 总览 |
| `/logs` | 日志查询 |
| `/projects` | 项目管理 |
| `/users` | 人员管理（仅系统管理员） |
| `/integrations` | 接入中心 |
| `/settings` | 基础诊断 |
| `/alerts` | 告警中心（V0.2 已实现，见第 11 节） |

Web API 的正式路径与 DTO 以文档 03 为准，不从前端随意新增接口。

### 13.2 前端组织建议

```text
LogPilot.Web/
  Views/
    Shared/_Layout.cshtml
    Home/Index.cshtml
    Logs/Index.cshtml
    Projects/Index.cshtml
    Users/Index.cshtml
    Integrations/Index.cshtml
    Settings/Index.cshtml
    Alerts/Index.cshtml
  wwwroot/
    css/site.css
    js/common/api-client.js
    js/common/ui-feedback.js
    js/pages/logs.js
    js/pages/projects.js
    js/pages/users.js
    js/pages/integrations.js
    js/pages/overview.js
    lib/echarts/            # 本地第三方静态文件（如 ECharts）
```

建议用 Razor 负责页面框架，原生 JS 负责高交互区域；避免内联脚本与页面渲染相互覆盖。第三方静态文件本地托管，不依赖公共 CDN。

### 13.3 状态与 API 约束

- 每个页面的交互脚本独立初始化，首版不引入复杂全局状态管理。
- 全部前端脚本为**原生 JavaScript + IIFE**（立即执行函数），无构建链、不引入 Vue/Element 等框架；请求统一通过 `LogPilotApi.api()` 封装发起。
- 所有写操作（`POST` / `PATCH` / `PUT` / `DELETE`）必须携带 `X-CSRF-TOKEN` 头。
- `api-client.js` 统一封装请求超时、凭证策略、错误展示；Cookie 会话与项目接入 Token 分离。
- 查询取消：更换过滤条件后取消旧请求或忽略旧响应，防止结果覆盖。
- 以 DTO 映射 UI，不把 VictoriaLogs 原始响应直接传到浏览器。
- 所有展示日志的组件对内容做文本转义，避免 XSS。

## 14. 响应式及无障碍验收

- 1440px、1024px、768px、390px 四种视口检查布局。
- 390px 下能完成登录、项目选择、搜索日志、查看详情、复制接入示例。
- Tab 键可到达主要按钮，Enter 可执行搜索，ESC 可关闭详情弹层。
- Dialog 焦点不能停留在遮罩下方控件。
- 重要状态含文字，不仅以红绿颜色区分。
- 长英文堆栈及中文混排不超出主视口，JSON 区域允许滚动。

## 15. 开发优先级与依赖关系

| 顺序 | 页面/组件 | 前置依赖 | 完成定义 |
|---|---|---|---|
| 1 | 基础布局、登录、初始化 | 会话 API、SQLite | 能登录进入空总览 |
| 2 | 项目管理 | 项目 API | 能创建、编辑、停用 |
| 3 | Token 和接入中心 | 密钥 API、双接入后端 | 能复制示例并真实写入日志 |
| 4 | 日志检索 | 搜索 API、筛选 API | 能按条件查询且权限隔离 |
| 5 | 日志详情 | 详情 API/日志定位方案 | 能安全展开、复制 JSON |
| 6 | 基础总览、设置诊断 | 健康 API | 正确显示存储状态 |
| 7 | 边界场景和响应式 | 以上全部 | 错误、空态、移动端可用 |

## 16. UI 验收清单

- [ ] 未初始化环境只出现管理员初始化入口；不能重复初始化。
- [ ] 未登录不能访问管理页面和 API。
- [ ] 多项目切换后不会保留其他项目日志结果。
- [ ] 能通过 OpenTelemetry SDK 把日志写入并在页面检索。
- [ ] 能通过 HTTP JSON 批量请求写入并在页面检索。
- [ ] 日志默认查询最近 15 分钟，并支持服务、级别、关键词、TraceId 筛选。
- [ ] 分页遵循后端真实稳定性边界；不会出现虚假的无限分页。
- [ ] 日志详情能展示堆栈和原始 JSON，复制成功有反馈。
- [ ] Token 只展示一次，撤销后无法继续接入。
- [ ] 健康异常时显示错误，不使用模拟正常状态。
- [ ] 告警中心三 Tab（事件/规则/渠道）均连接真实接口，不执行任何伪操作。
- [ ] 低分辨率浏览器、键盘操作、长文本场景均通过测试。
- [ ] 所有请求失败不影响已输入条件，也不泄露服务端内部堆栈。
